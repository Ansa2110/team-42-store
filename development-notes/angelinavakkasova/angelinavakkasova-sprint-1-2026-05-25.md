# Sprint 1 — the first Angular components

Сегодня впервые нормально работала с Angular и пыталась разобраться, как вообще устроены компоненты и структура проекта.

В рамках спринта занималась частью авторизации и создала несколько компонентов:

- LoginForm
- RegisterForm
- AuthPage

Также разбиралась, как Angular CLI генерирует компоненты и зачем нужны отдельные файлы `.ts`, `.html`, `.css` и `.spec.ts`.

---

## What was done:

Сначала развернула проект локально, установила зависимости и запустила приложение через `ng serve`.

После этого создала компоненты через Angular CLI:

```bash
npx ng generate component auth/login-form
npx ng generate component auth/register-form
npx ng generate component auth/auth-page
```

Сначала вообще не понимала, зачем создавать компоненты через терминал, потому что в React я обычно сама создаю файлы руками. Потом стало понятнее, что Angular CLI сразу создает правильную структуру компонента и тесты.

---

## LoginForm

В LoginForm сделала форму входа с полями email и password.

Использовала:
- interpolation `{{ }}`
- event binding `(click)`
- property binding `[disabled]`
- `input()`
- `output()`

Добавила базовую валидацию:
- пустой email;
- неправильный формат email;
- пустой пароль.

Самым непонятным сначала было то, как работает `output()` и зачем он нужен. Потом разобралась, что через него дочерний компонент может отправлять событие родителю, примерно как callback в React.

---

## RegisterForm

В RegisterForm сделала форму регистрации.

Добавила:
- имя;
- email;
- пароль;
- сообщения об ошибках.

Также сделала переключение между login/register через родительский компонент.

Пока без настоящего API — только UI и логика компонентов.

---

## AuthPage

AuthPage стал контейнером для login и register форм.

Тут впервые использовала `signal()` для переключения режима между входом и регистрацией.

Было интересно понять, что signals в Angular — это отдельная реактивная система и она работает иначе, чем state в React.

---

## Problems:

Сложнее всего было понять:
- как компоненты связываются друг с другом;
- зачем нужны standalone components;
- как работают signals.

---

## Solutions:

Сейчас проект:
- запускается;
- билдится;
- тесты проходят;
- компоненты отображаются;
- формы переключаются между login/register.

Также создала свою ветку `feat-auth`, сделала commit, push и pull request в `dev`.

За этот спринт более-менее разобралась:
